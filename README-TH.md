# Mumu Topup-Premium Store

## วิธีเปิดใช้งานบน Windows
1. แตกไฟล์ ZIP ไปยังโฟลเดอร์ใหม่
2. หากมีโฟลเดอร์โปรเจกต์เดิมที่ใช้งานอยู่ ให้สำรองโฟลเดอร์นั้นไว้ก่อน และอย่าลบฐานข้อมูล `data\\mumu.db`
3. คัดลอกไฟล์ `.env` จากโปรเจกต์เดิมมาไว้ข้าง `server.js` (อย่าแชร์ไฟล์ `.env` ให้ผู้อื่น)
4. เปิด CMD ในโฟลเดอร์โปรเจกต์ แล้วรัน `npm install` หากเป็นเครื่อง/โฟลเดอร์ใหม่
5. รัน `npm start`
6. เปิด `http://mumu-topup.local:3000` หรือ `http://localhost:3000`

## ดีไซน์ที่ปรับ
- เพิ่มเมนูด้านข้างแบบ hamburger พร้อมพื้นหลังกรมท่าเข้มและ accent ม่วงแบบพอดี
- เมนูย่อ/ขยายได้ ปิดด้วยปุ่ม X, แตะฉากหลัง หรือกด Escape
- มีทางลัดไปหน้าร้าน สินค้า ตะกร้า กระเป๋าเงิน ประวัติคำสั่งซื้อ และประวัติธุรกรรม
- แสดงสถานะผู้ใช้และยอดเงินเมื่อเข้าสู่ระบบ
- ปรับเอฟเฟกต์ให้เรียบขึ้นและลดแอนิเมชันที่เด่นเกินไป

## หมายเหตุสำคัญ
ZIP นี้ไม่รวม `.env` เพื่อปกป้องค่าตั้งค่าลับ และไม่รวมฐานข้อมูลจริง เพื่อไม่เขียนทับข้อมูลสมาชิก/ยอดเงิน/คำสั่งซื้อเดิม ให้ใช้ `.env` และ `data\\mumu.db` จากโปรเจกต์เดิมของคุณ


ธีมเวอร์ชันนี้ปรับหน้าร้านเป็นธีม Mumu Cat โทนกรมท่า/ม่วง พร้อมภาพมาสคอตในแบนเนอร์ และรองรับหน้าจอมือถือเพิ่มเติม โดยเก็บระบบเดิมไว้

## เข้าสู่ระบบหลังบ้าน (Admin)
1. เข้า `http://localhost:3000/admin` (หรือใช้โดเมนของร้านแล้วต่อท้าย `/admin`)
2. ถ้ายังไม่มีไฟล์ `.env` ให้คัดลอก `.env.example` เป็น `.env` ในโฟลเดอร์เดียวกับ `server.js`
3. เปิด `.env` แล้วตั้งค่าต่อไปนี้:
   - `ADMIN_USERNAME=admin` หรือชื่อผู้ใช้แอดมินที่ต้องการ
   - `ADMIN_PASSWORD=` ใส่รหัสผ่านใหม่ที่คาดเดายากและไม่ซ้ำกับบัญชีอื่น
   - `SESSION_SECRET=` ใส่ค่าสุ่มที่ยาวและคาดเดายาก โดยสร้างค่าใหม่เฉพาะสำหรับการติดตั้งนี้ ห้ามเปิดเผยหรือใช้ค่าตัวอย่างเป็นค่าจริง
4. ตั้งค่า `PROMPTPAY_ID` ตามบัญชีที่ต้องการรับชำระเงิน หากยังไม่พร้อมใช้งาน ให้เว้นว่างไว้ก่อน
5. ห้ามส่งไฟล์ `.env` ให้ผู้อื่น และห้ามนำไฟล์นี้ใส่ใน ZIP ที่แจกจ่าย
6. หยุดเซิร์ฟเวอร์ด้วย `Ctrl+C` แล้วรัน `npm start` ใหม่ เพื่อให้ระบบอ่านค่าจาก `.env`
7. ใช้ชื่อผู้ใช้และรหัสผ่านตามค่าใน `.env` เข้าสู่ระบบหลังบ้าน
8. ก่อนเปิดให้ผู้ใช้ทั่วไปเข้าถึง ต้องตรวจสอบการตั้งค่าความปลอดภัยและทดสอบฟังก์ชันสำคัญให้ครบก่อน
**กู้คืนรหัสผ่านแอดมิน:** ตั้ง `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ใน `.env` แล้วรีสตาร์ตเซิร์ฟเวอร์ ระบบจะอัปเดตรหัสผ่านของชื่อผู้ใช้นั้นให้โดยไม่ต้องลบฐานข้อมูล หากเปลี่ยน `ADMIN_USERNAME` เป็นชื่อใหม่ ระบบจะสร้างบัญชีแอดมินชื่อนั้นเพิ่มให้

**สำคัญ:** ห้ามลบ `data\mumu.db` เพื่อแก้ปัญหาล็อกอิน เพราะไฟล์นี้อาจมีสมาชิก ยอดเงิน และคำสั่งซื้อเดิม

## อนุมัติคำสั่งซื้อหลายรายการพร้อมกัน
1. เข้า `/admin` และเปิดแท็บจัดการคำสั่งซื้อ
2. เลือกช่องสี่เหลี่ยมหน้าออเดอร์ที่มีสถานะรอดำเนินการ หรือใช้ช่องบนหัวตารางเพื่อเลือกออเดอร์ที่รอดำเนินการทั้งหมดในรายการที่แสดง
3. กด **อนุมัติที่เลือก**
4. ตรวจสอบแต่ละออเดอร์ และกรอกข้อความ/รหัสส่งมอบแยกแต่ละรายการ
5. กด **อนุมัติรายการที่เลือกทั้งหมด** เพื่อตั้งสถานะสำเร็จในครั้งเดียว

ระบบจะทำรายการแบบ transaction: หากออเดอร์ใดไม่อยู่ในสถานะรอดำเนินการแล้ว ระบบจะยกเลิกชุดการอนุมัติทั้งหมดเพื่อป้องกันการอนุมัติไม่ครบชุด

## ค้นหาสมาชิกก่อนปรับยอด Wallet
- ในแท็บจัดการสมาชิก/ปรับยอด Wallet ใช้ช่องค้นหาเพื่อกรองรายชื่อได้ทันที
- ค้นหาด้วยชื่อสมาชิก อีเมล หรือ Member ID ได้ รวมถึงพิมพ์เพียงบางส่วนของชื่อหรืออีเมล
- ตรวจสอบชื่อ อีเมล และยอดเงินที่แสดงก่อนกดเพิ่มเงินหรือหักเงิน
- ระบบนี้ใช้ชื่อและอีเมลที่มีอยู่ในฐานข้อมูลเดิม ไม่ได้เพิ่มหรือเปลี่ยนข้อมูลสมาชิก


## การจัดการคำสั่งซื้อแยกตามสมาชิก (อัปเดต)
- หน้า Admin > จัดการคำสั่งซื้อ จัดกลุ่มออเดอร์ตามบัญชีสมาชิกและแสดงชื่อ อีเมล และ Member ID
- ค้นหาสมาชิกด้วยชื่อ อีเมล หรือ Member ID ได้
- เลือกออเดอร์ที่รออนุมัติจากกลุ่มของสมาชิกคนนั้น และอนุมัติหลายรายการของสมาชิกคนเดียวกันได้
- ฝั่งเซิร์ฟเวอร์ปฏิเสธการอนุมัติแบบกลุ่มที่มีออเดอร์จากหลายบัญชีปะปนกัน
- ไม่รวมฐานข้อมูลจริงหรือไฟล์ `.env` ไว้ใน ZIP; สำรองฐานข้อมูลเดิมก่อนอัปเดตเสมอ

## เปิดเว็บทดสอบจาก iPad ใน Wi‑Fi เดียวกัน
1. เชื่อมต่อคอมพิวเตอร์และ iPad เข้ากับเครือข่าย Wi‑Fi เดียวกัน (อย่าใช้ Guest Wi‑Fi ที่แยกอุปกรณ์)
2. เปิด Command Prompt บนคอมพิวเตอร์ แล้วพิมพ์ `ipconfig`
3. หา `IPv4 Address` ของอะแดปเตอร์ Wi‑Fi เช่น `192.168.1.25` (ใช้ IP ของคอมพิวเตอร์ ไม่ใช่ `127.0.0.1`)
4. รันเซิร์ฟเวอร์ด้วย `npm start` ตามปกติ และปล่อยหน้าต่างนี้เปิดค้างไว้
5. บน iPad เปิด Safari แล้วเข้า `http://<IPv4-Address-ของคอม>:3000` เช่น `http://192.168.1.25:3000`
6. ถ้า Windows Firewall ถาม ให้เลือกอนุญาตเฉพาะ **Private networks** สำหรับ Node.js เท่านั้น หากไม่มีหน้าต่างถามและเข้าไม่ได้ ให้ผู้ดูแลเครื่องเพิ่มกฎอนุญาต TCP port 3000 เฉพาะเครือข่าย Private
7. หาก IP ของคอมเปลี่ยน ให้รัน `ipconfig` ใหม่แล้วใช้ IPv4 ล่าสุด

**ความปลอดภัย:** วิธีนี้มีไว้สำหรับทดสอบในเครือข่ายส่วนตัวที่ไว้ใจได้เท่านั้น อย่าเปิด port forwarding ที่เราเตอร์หรือเปิดเว็บนี้สู่สาธารณะ และอย่าใช้ Wi‑Fi สาธารณะในการทดสอบบัญชีจริง/ข้อมูลจริง หากทดสอบการล็อกอินหลายบัญชี ให้ใช้ Safari บน iPad กับเบราว์เซอร์บนคอมซึ่งมีคุกกี้แยกกัน
